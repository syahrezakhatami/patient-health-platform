# Database conventions

## Identifiers

- Primary keys are UUIDs generated by the platform or the database.
- NIK, BPJS ID, MRN, passport, phone, and email are identifiers, never primary keys.
- Foreign keys are named `<entity>_id`.

## Naming

- Tables: `snake_case`, plural (`audit_events`).
- Columns: `snake_case`.
- Indexes and constraints follow SQLAlchemy naming: `pk_`, `fk_`, `uq_`, `ix_`, `ck_`.

## Timestamps

Infrastructure timestamps:

- `created_at`
- `updated_at`

Clinical timestamps (later waves — do not substitute `created_at`):

- `clinical_effective_at` — when the event happened in the world
- `recorded_at` — when a clinician recorded it
- `imported_at` — when this platform received it

## Integrity

Wave 0 requires foreign keys, unique constraints, CHECK constraints, and NOT NULL on required columns as tables appear.

Application startup must never run migrations. Use Alembic explicitly.

## Roles (target model)

| Role | Purpose |
|---|---|
| `migrator` | DDL / Alembic |
| `app_dml` | Application DML; no schema changes; no audit UPDATE/DELETE |
| `app_audit_insert` | Insert-only audit writer if separated |
| `readonly` | Selected reads |

The runtime application user must not be a superuser.

Local Docker creates these roles with synthetic passwords. Production credentials come from a secret manager.
